# Brick — CAD workflow: агент + GitHub + просмотр результата (рекомендация, 2026-10-20)

**Назначение:** параметрическая редактируемая 3D-модель корпуса Brick с тремя расцветками, без копирования неверной графики из рендеров. Масштабирование, STL/STEP, производство тестовых корпусов и непрерывная проверка геометрии. Документ описывает **предлагаемый** инженерный процесс, не утверждённое программное обеспечение.

## Рекомендация: код — в приватном GitHub, вычисление — в CI/облачном агенте, просмотр — в FreeCAD локально

**Источник истины — параметрический Python-код**, а не импортированный STEP. **CadQuery 2.x** (или build123d при обосновании агентом) строит OpenCascade B-Rep, позволяет отдельно экспортировать детали STEP и STL и собирать одну и ту же master-модель в разных финишах. CAD-агент правит скрипты, запускает генератор и прикладывает к PR артефакты/изображения. На компьютере владельца FreeCAD служит для просмотра сечений, измерений, STEP/STL и обратной связи.

Почему подходит: изменения корпуса и кнопок выражаются diff в Git; CI позволяет автоматически повторить точные версии генератора, проверить отсутствие пересечений и выдавать STL для печати; нет зависимости от платной подписки и публичных документов. **Не требуется держать локальный CAD-сеанс работающим для того, чтобы агент вычислил геометрию в CI.**

### Обязательные файлы первого CAD-PR

```text
mechanical/
├── README.md                   # reproducible commands and dependencies
├── params.json                 # 175×80×20/22, buttons, openings, tolerances
├── src/
│   ├── case.py                 # front/rear shells, seam, bosses (prototype)
│   ├── keys.py                 # 4 separate yellow direction + 1 action + 3 function
│   ├── display.py              # LCD/Azumo placeholder (NOT approved real component)
│   ├── internals.py            # PCB/battery/speaker placeholders
│   └── build.py                # assemble, validate, export
├── exports/                    # Git LFS or CI artifacts when STEP/STL are large
│   ├── brick-r02-assembly.step
│   ├── front-shell.stl
│   └── rear-shell.stl
├── renders/                    # isometric, front, side, rear, exploded, section views
└── validation.md               # bounding boxes, clashes, constraints, unverified dims
```

### Автоматизированные проверки

1. Bounding box корпуса: **175×80**, выбор 20 и 22 мм из параметров, проверка ориентации осей и прямоты боков.
2. 4 независимые направления, Ø≈8.5–9 мм, без общей крестовины; межкнопочный зазор на бумажном чертеже + проверка реального хвата на 1:1 печати.
3. 3 функции MODE/SELECT/START **под** LCD (не под игровой зоной) и одна гладкая Action.
4. Нижний торец: **только USB-C**; никаких отверстий для динамика или microSD.
5. Единственный порт динамика: **спереди, ближе к нижнему центру**.
6. Детали физически раздельные и экспортируются в STEP; на намеренные места контакта делать допуски, на случайные пересечения — отчёт.
7. Одинаковая master geometry Monolith/Clear Smoke/Ceramic: только appearance и материал отличаются; реальная усадка пластика требует DFM.
8. LCD **пока кандидат Sharp LS032B7DD02**; его FPC/frontlight, LED, корпусная толщина и refresh должны подтвердиться документацией и прототипом. Модель дисплея — заменяемый параметрический placeholder.
9. Возможность получить STL для физического макета, включая отдельные клавиши, и напечатать в масштабе 1:1.

## Локальный просмотр

Бесплатный [FreeCAD](https://www.freecad.org/) для Windows/macOS/Linux, включая Apple Silicon. Используй прежде всего для **открытия STEP/разрезов/измерений**. Он может редактировать геометрию, но импорт STEP **не восстановит** автоматически исходную Python-параметрическую историю CadQuery. Если важно править модель вручную именно в FreeCAD tree, попросить агента альтернативно создать нативный `.FCStd` скриптом FreeCAD Python/FreeCADCmd. Это отдельный критерий выбора CAD-стека.

- Для самой первой модели не нужно покупать Fusion 360/SolidWorks/Onshape.
- CAD-агенту не обязательно иметь доступ к установленному FreeCAD на личном ПК владельца: ему нужен воспроизводимый CAD-контейнер в собственной среде или в GitHub Actions.
- На локальном ПК можно запускать ту же команду контейнера/окружения CAD и открывать результат в FreeCAD.
- После включения CAD-CI результаты STEP/STL должны сохраняться как GitHub Actions artifacts и/или в PR, **не заявлять что workflow работает, пока его не реализовали и не протестировали**.

## Альтернатива 100% в браузере: Onshape

Onshape — полноценный браузерный параметрический CAD, позволяет редактировать компоненты и сборки совместно. [FeatureScript](https://cad.onshape.com/FsDoc/index.html) — язык параметрических фич; [Onshape API](https://onshape-public.github.io/docs/api-adv/featureaccess/) позволяет облачному агенту программно создавать и изменять CAD. Onshape Labs уже описывал **FeatureScript MCP Server** для текст → код → CAD: https://www.onshape.com/en/blog/featurescript-mcp-server-enables-text-code-cad .

**Однако на бесплатном Onshape все документы публичны и разрешено только некоммерческое использование** — НЕ подходит текущему **приватному потенциально коммерческому устройству**. На 2026-10-20 официальный Standard для приватных коммерческих CAD — **$1500/пользователь/год**, Professional — $2500/пользователь/год; источник https://www.onshape.com/en/pricing . Пробную версию/ограничения можно проверить перед подпиской. Автоматическая работа агента через Onshape API/FeatureScript нуждается в отдельной авторизации и настройке; из одного существования GitHub-репозитория доступ к Onshape не появляется.

## Выбор

| Критерий | CadQuery + GitHub Actions + FreeCAD | Onshape + FeatureScript/API |
| --- | --- | --- |
| Приватность проекта | Приватный GitHub + закрытые CI artifacts | Требуется платный private план |
| Базовая стоимость | Open source / вычислительные минуты CI | Standard от $1500/год за пользователя |
| Запуск агентом | Через Python-код/CI, воспроизводимо | Через API и/или FeatureScript при настройке доступа |
| Локальная установка для владельца | **FreeCAD желателен лишь для просмотра/редактирования** | Не нужна |
| Параметрическая история | Код CadQuery — source of truth | Нативное дерево фич в Onshape |
| Экспорт в производство | STEP, STL (создать через скрипт) | STEP, STL и др. |
| Поддержка 3D-печати прототипа | Отлично | Отлично |
| Поддержка сложных поверхностей | Возможно, но может потребовать ручной CAD-доработки | Сильная native feature / surfacing система |

**Вывод:** начать с **CadQuery + GitHub Actions**, владелец ставит **FreeCAD** по желанию для просмотра. Если станет важнее интерактивное редактирование сложной поверхности оболочки из браузера и агентская работа непосредственно над деревом фич, рассмотреть платный Onshape. Не смешивать два независимых источника истины для корпуса в первых ревизиях.
