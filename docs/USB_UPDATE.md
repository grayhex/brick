# Обновление и восстановление Brick по USB-C (черновик)

**Статус: ЧЕРНОВИК, НЕ ПРОВЕРЕНО на устройстве.** Инструкция описывает задуманный порядок; утилита [`tools/dfu/brick_dfu.py`](../tools/dfu/brick_dfu.py) написана и проверена на имитации устройства, но не запускалась с настоящей платой ([NRF52840_BRINGUP.md](NRF52840_BRINGUP.md), [план испытаний](../platform/nrf52840/tests/HIL_TESTPLAN.md)). Сейчас порядок можно пробовать **только** на плате разработчика nRF52840 DK с dev-ключом. Прошивки для покупателей и их подпись — позже ([FIRMWARE_UPDATE_NRF52840.md](FIRMWARE_UPDATE_NRF52840.md)).

Как это устроено: новую подписанную прошивку утилита по кабелю USB-C кладёт во второй слот памяти и просит загрузчик MCUboot **попробовать** её один раз. Если новая прошивка запустилась и сама подтвердила себя после самопроверки — она остаётся. Если нет (не запустилась, зависла, не подтвердилась) — при следующей перезагрузке загрузчик возвращает прежнюю. Утилита **никогда не подтверждает прошивку сама**.

## Подготовка (один раз)

Нужны Python 3.10 или новее и файл прошивки `zephyr.signed.bin` (собирается `platform/nrf52840/scripts/build.sh`).

```sh
python3 -m venv brick-dfu-venv
. brick-dfu-venv/bin/activate            # Windows (PowerShell): brick-dfu-venv\Scripts\Activate.ps1
python -m pip install -r tools/dfu/requirements.txt
```

* **Linux.** Порт называется `/dev/ttyACM0` (или `ACM1` …). Нужен доступ: добавьте себя в группу `dialout` (Debian/Ubuntu) или `uucp` (Arch/Fedora) и войдите заново. Если порт «занят» на секунды после подключения, это может быть ModemManager — отключите его для устройства правилом udev (`ENV{ID_MM_DEVICE_IGNORE}="1"`) или остановите службу на время обновления.
* **macOS.** Порт называется `/dev/cu.usbmodem…`; драйверов не нужно.
* **Windows 10/11.** Порт называется `COM3` (номер любой); обычно ставится встроенный драйвер USB-последовательного порта. Если устройство видно как «неизвестное», откройте Диспетчер устройств и укажите драйвер «USB-последовательное устройство»; номер порта может **поменяться после перезагрузки платы** — утилита ищет порт заново.

## Обновление

1. Подключите Brick (на разработческой плате — разъём **nRF USB**, не отладочный) кабелем USB-C.
2. Проверьте связь и состояние:
   ```sh
   python tools/dfu/brick_dfu.py status
   ```
   Должны появиться загрузчик и слот 0 с вашей версией: флаги `active` и `confirmed`.
3. Обновите:
   ```sh
   python tools/dfu/brick_dfu.py update zephyr.signed.bin
   ```
   Утилита загружает файл, помечает его для пробного запуска, перезагружает устройство (загрузчик переставляет слоты — это занимает время, не отключайте кабель), ждёт его возвращения и печатает итог:
   * `new image runs and is confirmed` — готово (код возврата 0);
   * `new image runs but is NOT confirmed` — новая прошивка работает, но не подтвердила себя; при следующей перезагрузке вернётся прежняя (код 3);
   * `the new image is NOT running` — загрузчик отверг или откатил новую (код 2): проверьте файл и ключ подписи.
4. Если связь оборвалась во время загрузки — подключите заново и повторите шаг 3: прежняя прошивка остаётся рабочей.

Отдельные команды: `ports` (найти устройства), `upload FILE` (только загрузить), `test` (пробный запуск при следующей перезагрузке), `reset` (перезагрузить).

## Восстановление, если прошивка не запускается

Загрузчик MCUboot умеет принимать прошивку по USB **независимо от приложения**.

1. Отключите питание. На Brick удерживайте **MODE** (задуманная комбинация; на разработческой плате — **Button 1**), подключите USB-C и держите несколько секунд. Если допустимого приложения нет вовсе, загрузчик входит в режим восстановления **сам**, кнопка не нужна.
2. `python tools/dfu/brick_dfu.py ports` — должен показать порт с ролью `recovery`.
3. `python tools/dfu/brick_dfu.py recover zephyr.signed.bin` — запись прошивки в основной слот и перезагрузка. Загрузчик снова проверяет подпись; прошивка с чужой подписью не запустится.

Режим восстановления **не подтверждён испытаниями** (T05–T07 плана). Если плата не отвечает и после этого — паяльные контакты SWD остаются сервисным путём ([FIRMWARE_UPDATE_NRF52840.md](FIRMWARE_UPDATE_NRF52840.md) п.7).

## Чего эта инструкция не обещает

Проверенной работы на реальном устройстве; времени обновления; поведения при обрыве питания в середине перестановки слотов (испытание T14); работы с конкретной версией Windows/macOS/Linux; подписи релизных прошивок (она создаётся вне репозитория и пока не существует).
