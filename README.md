# Brick — премиальная карманная Brick Game

**Статус:** концепт / до прототипа железа; **добавлен первый программный прототип** (переносимое игровое ядро, Tetris, Snake, меню, ПК-симулятор — см. ниже). **Видимость:** закрытый репозиторий. **Язык документов:** русский.

Оригинальная премиальная аккумуляторная карманная игра по мотивам классических вертикальных устройств Brick Game. Упор на подлинную строго монохромную пиксельную графику, физические кнопки, качественный звук, долгую работу от батареи и обновляемую прошивку; это не эмулятор универсальной игровой консоли.

> [!IMPORTANT]
> Репозиторий на стадии требований и исследования. Ни процессор, ни панель LCD, ни батарея, ни плата, ни размеры корпуса не утверждены к производству. См. `docs/PRODUCT_REQUIREMENTS.md` и `docs/HARDWARE_RESEARCH.md`.

## Подтверждённое направление продукта

- Большой узнаваемый **классический силуэт Brick Game** в современном исполнении, не мини-консоль.
- **ПОДТВЕРЖДЕНО: позитивное монохромное изображение LCD:** тёмные (чёрные) пиксели на светлом нейтрально-сером отражающем фоне; читается без подсветки при достаточном внешнем свете; необязательная **слабая белая подсветка** только для темноты. Негативной темы (светлые пиксели на чёрном), градаций серого и цвета в интерфейсе нет. Технология панели и способ подсветки пока не выбраны.
- **Четыре отдельные небольшие жёлтые круглые кнопки направлений**, **одна большая гладкая жёлтая кнопка действия** и **три подписанные жёлтые функциональные кнопки прямо ПОД экраном (MODE / SELECT / START)**; кроме них физический выключатель питания и колесо или ползунок громкости.
- Разъём USB-C **по центру нижней грани — единственное отверстие**, разъёма 3,5 мм нет; **одна решётка динамика на ЛИЦЕВОЙ стороне у нижнего центра**.
- **BLE нужен для связи с телефоном, настроек и синхронизации. Весь звук идёт через встроенный динамик; наушники по Bluetooth не поддерживаются и не нужны.**
- Цель — **20–30 часов** работы по точно описанному профилю испытаний; аккумулятор с зарядкой.
- В продукте цель — около **10 классических игр**, дальше — обновлениями прошивки. **Первая версия прошивки — четыре игры: Tetris, гонки (Racing), Snake и Tank** (решение владельца, ADR-034); Dice портировать не нужно.
- Правила игр и регрессионные фикстуры берутся из [grayhex/ApolloBrickGames](https://github.com/grayhex/ApolloBrickGames); браузерный код на TypeScript не переносится на микроконтроллер как есть.
- Первая партия: **100–500 штук**. Репозиторий пока закрытый.

## Программный прототип (0.1)

Переносимое игровое ядро на C11, не привязанное к дисплею, разрешению, MCU или плате (ADR-023…034):

- **Ядро** `firmware/`: игра — структура без динамической памяти с таблицей функций, фиксированный такт 60 Гц, детерминированный ГСЧ, ни кучи, ни глобального состояния; граница с железом — `bk_hal_t` (ввод, дисплей, звук, хранилище, подсветка).
- **Tetris, базовый вариант 01**, перенесён из [ApolloBrickGames](https://github.com/grayhex/ApolloBrickGames) и **сверяется с эталоном на каждом такте**: 68 сценариев, 59 357 тактов ([docs/CONFORMANCE.md](docs/CONFORMANCE.md)). Остальные 50 вариантов пока не нужны ([docs/GAME_TETRIS.md](docs/GAME_TETRIS.md)).
- **Snake, варианты 01 и 02 («FRAME»)** — вторая игра на общей основе (жизни, сцены очистки поля): сверка на каждом такте, **72 сценария, 84 588 тактов**. Игры выбираются в меню клавишами влево/вправо.
- **ПК-симулятор** (терминал и браузер, ядро как WebAssembly) — [docs/SIMULATOR.md](docs/SIMULATOR.md).
- **Экран:** 1-битный логический кадр, позитивная полярность, поле 10×20 и статус-колонка справа; эталонная сетка и **подгонка под нативный размер панели** (клетка 26 точек и колонка 76 точек для 336×536); ограничитель частоты показа `max_fps` — 60 Гц это частота симуляции, а не панели ([docs/UI_MENU.md](docs/UI_MENU.md)).
- **Меню:** номер или буква игры, номер режима, миниатюра, SPEED / LEVEL, настройки; четыре кнопки направлений, одна кнопка действия и кнопки MODE / SELECT / START (физический набор подтверждён в PRD).
- Размер ядра с двумя играми под Cortex-M4F: ≈ 26,8 КБ flash (26 778 Б), `.data` и `.bss` равны 0 (**только компиляция**, на железе не измерялось).

```sh
cmake -S . -B build -G Ninja && cmake --build build && ctest --test-dir build --output-on-failure
cmake -S . -B build-asan -G Ninja -DBRICK_SANITIZE=ON && cmake --build build-asan && ctest --test-dir build-asan   # ASan + UBSan
cmake -S . -B build-m4 -G Ninja -DCMAKE_TOOLCHAIN_FILE=cmake/arm-none-eabi.cmake -DCMAKE_BUILD_TYPE=Release -DBRICK_BUILD_TESTS=OFF \
  && cmake --build build-m4 && cmake --build build-m4 --target brickcore_size                                       # проверка переносимости
```

Нужны CMake ≥ 3.16 и компилятор C11/C++17; Node ≥ 20 — только для перегенерации фикстур соответствия.

## Ближайшие приоритеты

1. Проверить два семейства монохромных отражающих дисплеев **на живых образцах**, включая белую подсветку и видимость при выключенном свете; для Snake и будущих игр — играбельность при 10, 15, 20 и 30 кадрах в секунду (риски R-9, R-10).
2. Сделать прототип BLE-связи с телефоном для настройки и синхронизации; потоковой передачи звука нет.
3. Довести первую версию прошивки: порт **Racing**, затем **Tank**; проверить, хватает ли одной кнопки действия для всех четырёх игр.
4. Измерить энергопотребление и задержку обновления кадра для кандидатов MCU + LCD + звук.
5. По текущим рисункам R0.2 и заданию для CAD сделать прототип эргономики и акустики **до** того, как фиксировать контур платы и заказывать оснастку.

FPGA не оправдан одной лишь механикой классических Brick Game; рассматривать его, только если точное аппаратное воспроизведение станет отдельным явным требованием.
