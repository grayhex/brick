## Стенд

| Что | Требование |
| --- | --- |
| Плата | Nordic nRF52840 DK (PCA10056), прошивка интерфейсного МК J-Link актуальная; номер партии и серийный номер записать |
| Кабели | два USB: **отладочный** (разъём с надписью DEBUG — прошивка и виртуальный COM, журнал приложения 115200 8N1) и **nRF USB** (разъём самого nRF52840 — обновление и recovery). Не путать: `brick_dfu.py` работает только через nRF USB |
| Питание | DK питается от отладочного USB; для проверок обрыва питания — управляемый разрыв линии питания/USB (реле, умная розетка USB-хаба или ручное выдёргивание с записью времени) |
| ПК | Linux, Windows и macOS (хотя бы по одному запуску T03–T08 на каждой системе) |
| ПО | NCS v3.4.1 (`setup_ncs.sh`), nrfutil или nrfjprog, Python 3.10+ с `tools/dfu/requirements.txt` |
| Образы | `scripts/build.sh` в вариантах `release` (0.1.0 и `--sign-version 0.2.0+0`), `noconfirm`, `crash`, `hang` (все 0.2.0+0) **одним и тем же dev-ключом** и ещё образ, подписанный другим ключом |
| Журналы | каждое испытание: полный журнал UART0, вывод `brick_dfu.py`, версии инструментов → `platform/nrf52840/tests/results/<дата>-<плата>/` |

## Испытания

Ожидания — это **гипотезы из документации**, а не результаты. Отличие от ожидания записывается как есть.

| № | Что проверяется | Шаги | Ожидаемо |
| --- | --- | --- | --- |
| T01 | Первая прошивка и запуск | `west flash -d <build>` (или `nrfutil device program --firmware brick-dk-initial.hex --options chip_erase_mode=ERASE_ALL`); смотреть UART0 | Журнал: версия `0.1.0`, `image: confirmed=NO (test)` (образ прошит программатором, трейлера нет), затем `self-test passed, confirm image: OK`, `ready`; светодиод LED1 мигает раз в секунду. Записать время запуска и реальные строки |
| T02 | Карта и размеры на плате | В журнале T01 строки `flash area ...` | `slot0` 0x020000 / 768 КиБ, `slot1` на QSPI 768 КиБ, `storage` 0x0E0000 / 128 КиБ — как в `NRF52840_BRINGUP.md` §3; приложить |
| T03 | Приложение перечисляется по USB | nRF USB подключён; `brick_dfu.py ports` | один порт, роль `app`; записать имя порта (COMn, /dev/ttyACM*, /dev/cu.usbmodem*) на каждой ОС |
| T04 | SMP в приложении | `brick_dfu.py status` | загрузчик MCUboot, режим swap без scratch; слот 0: версия `0.1.0`, `active`, `confirmed` |
| T05 | Serial recovery по кнопке | Удерживая Button 1 (SW1), нажать RESET; отпустить; `brick_dfu.py ports` | порт роль `recovery` (имя «Brick V1 recovery (DEV)»); `status` показывает слот 0. Плата остаётся в recovery **дольше 5 с** (сторожевой таймер приложения переживает мягкий сброс; MCUboot должен его кормить) |
| T06 | Recovery без работающего приложения, **без SWD** | Испортить приложение (прошить в `slot0` образ с изменённым байтом через SWD **один раз**), сбросить плату **без** кнопки; затем только `brick_dfu.py recover zephyr.signed.bin` | MCUboot остаётся в recovery сам (`BOOT_SERIAL_NO_APPLICATION`), порт `recovery`; после `recover` приложение запускается. Если плата просто «молчит» — это отказ, записать |
| T07 | Recovery принимает только подписанное | В recovery загрузить образ, подписанный другим ключом; сбросить | MCUboot образ не запускает; остаётся/возвращается в recovery; `recover` правильным образом восстанавливает |
| T08 | Обновление → подтверждение | Из 0.1.0: `brick_dfu.py update` образом `release` 0.2.0 | пробный запуск → swap → приложение 0.2.0 подтверждает → итог `new image runs and is confirmed`; `status`: слот 0 — 0.2.0 `active confirmed`, слот 1 — 0.1.0. Записать **время всей операции и время swap**; в ходе swap нет лишних сбросов от сторожевого таймера (он запущен прежним приложением и переживает сброс) |
| T09 | Откат: образ не подтверждён | `update` вариантом `noconfirm`; затем `reset` | после `update`: итог «runs but is NOT confirmed»; после `reset` MCUboot возвращает предыдущую версию (проверить `status`) |
| T10 | Откат: падение до подтверждения | то же вариантом `crash` | устройство перезагружается, затем стабильно работает **предыдущая** версия; записать число перезагрузок |
| T11 | Откат: зависание | то же вариантом `hang` | через ≈5 с сторожевой таймер → сброс → предыдущая версия |
| T12 | Неверная подпись | загрузить образ с испорченным байтом (после подписи) и образ другого ключа командами `upload` и `test`, затем `reset` | MCUboot отвергает; работает прежняя версия; слот 1 очищен или помечен недействительным (записать фактическое состояние) |
| T13 | Обрыв передачи | во время `upload` выдернуть nRF USB (в начале, середине, конце); подключить; `status` | прежняя версия работает; повторный `update` успешен |
| T14 | Обрыв питания в swap | `update`; после `reset` отключать питание в ≥ 20 разных моментах swap (равномерно по времени swap из T08, случайно) | **после каждого** возвращения питания работает целая версия — старая либо новая; ни одного «кирпича»; серия записывается (момент, результат) |
| T15 | Настройки не затронуты | записать метку в `storage_partition` (отладчик), выполнить T08 и T09, прочитать | метка цела |
| T16 | ОС: Windows / macOS / Linux | T03–T08 на каждой | записать драйвер/права/ModemManager (Linux), имена портов |
| T17 | Устойчивость под нагрузкой | 20 циклов `update` туда-обратно | без ошибок; время цикла; износ не оценивать по числу, только отметить |
